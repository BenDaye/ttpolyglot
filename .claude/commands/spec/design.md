# 任务

为已批准的需求规格创建技术设计文档和任务分解。

## 前置条件

- `.spec-workflow/specs/active/{spec-name}/requirements.md` 存在且状态为 `approved`

## 流程

### 第 1 步：分析需求

1. 读取 requirements.md
2. 使用 Serena 分析相关代码结构
3. 识别需要修改的文件和新增的文件

### 第 2 步：技术访谈（2 轮）

**第 1 轮：方案设计**
- 整体实现方案？
- 需要新增的模型/API/页面？
- 数据库迁移需求？

**第 2 轮：确认细节**
- 涉及哪些现有文件的修改？
- 前后端接口契约？
- 测试策略？

### 第 3 步：生成 design.md

```markdown
# {功能名称} - 技术设计

## 方案概述
{整体实现方案}

## 变更清单

### 新增文件
- `{路径}` - {用途}

### 修改文件
- `{路径}` - {修改内容}

### 数据库变更
- 迁移: {描述}

### API 变更
- `{方法} /api/v1/{路径}` - {描述}

## 数据流
{请求从前端到后端的完整数据流}

## 技术决策
{关键技术选择及理由}
```

### 第 4 步：生成 tasks.md

```markdown
# {功能名称} - 任务分解

## 任务列表

### 1. {任务组名}

- [ ] **1.1** {任务描述}
  - 文件: `{文件路径}`
  - 目的: {目的}
  - 要求: {具体要求}

- [ ] **1.2** {任务描述}
  ...

### 2. {任务组名}
...

## 执行顺序

{建议的执行顺序和依赖关系}

## 估算

| 任务组 | 预估 SP |
|--------|---------|
| 1. {名称} | {SP} |
| 总计 | {SP} |
```

### SP 估算参考

| SP | 复杂度 | 示例 |
|----|--------|------|
| 1 | 简单修改 | 修改一个字段、调整样式 |
| 2 | 小功能 | 新增一个 API 端点、添加一个简单页面 |
| 3 | 中等功能 | 新增 CRUD 完整流程 |
| 5 | 较大功能 | 跨前后端的完整功能模块 |
| 8 | 大型功能 | 涉及多个包的复杂功能 |

> SP > 5 的任务应考虑拆分
